The challenge

Privacy and security are pulling in opposite directions

IPv6 privacy extensions protect users from tracking by rotating device addresses. That same rotation blinds traditional security monitoring.

IP-based monitoring breaks

Each rotation looks like a brand-new host. Per-device baselines reset, and a compromised device can dodge an IP block just by changing its address.

The usual fix creates tracking

Logging MAC and IP pairs restores visibility, but it builds exactly the identity database the privacy extensions were designed to prevent.

VEIL6 delivers both

VEIL6 links rotating addresses to a keyed pseudonymous session, then detects and attributes attacks to it. No raw identifier is ever written down.

How it works

A six-stage, privacy-first pipeline

Raw identifiers are converted to pseudonyms at the first point they're seen. Every stage after that works only with pseudonyms.

01 · IoT Lab

Virtual IPv6 devices

The lab has cameras, smart locks, a thermostat, sensors, plugs, a hub and a phone on 2001:db8:a10e:1::/64, using RFC 7217 stable addresses and RFC 8981 rotation.

02 · Capture

Metadata only

The gateway reads flow headers only: addresses, ports, protocol, size and ICMPv6 type. It never reads payloads.

03 · Session Mapper

Pseudonymize at ingest

NDP NS/NA/DAD bindings become HMAC(K_epoch, MAC) sessions. Table entries expire with the address lifetime.

04 · Rule Engine

Eight sliding-window rules

Rules run per session, per target and per pair. A learned destination profile catches exfiltration to hosts the device has never contacted.

05 · Alerts

Pseudonymous & MITRE-tagged

Each alert carries the session, the target, the evidence and the ATT&CK technique. That's enough for a SOC analyst to act on, with no personal identifier inside.

06 · Evaluator

Measured, not claimed

Controlled attacks carry ground truth, so every run reports precision, recall, latency, attribution and a leak audit.

Privacy by design

What VEIL6 deliberately never keeps

VEIL6 has no privacy setting to switch on. The architecture enforces it, and an automated audit verifies it on every run.
